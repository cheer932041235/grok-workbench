# 历史记录与子任务开发方案

## 目标

让 Grok Workbench 能管理长期积累的会话，清楚呈现主任务与子任务，并保持发送、排队、归档和恢复行为一致。实现范围面向本机 Grok CLI、Windows 桌面和已有 ACP 连接。

## 模块与数据流

| 模块 | 职责 | 验收点 |
| --- | --- | --- |
| Rust 历史存储 | 保存正文、读取摘要、按 ID 读取正文 | 列表响应不含正文或图片；旧数据可读取 |
| Grok 历史导入 | 读取 CLI 会话元数据及事件记录 | 不改动源文件；重复导入不覆盖工作台记录 |
| 页面历史协调 | 搜索、打开、重命名、归档、导入提示 | 操作串行；当前草稿先保存；归档不丢正文 |
| 会话事件处理 | 按 sessionId 分流 ACP 与扩展通知 | 子任务文本和工具不会混入主对话 |
| 子任务卡片 | 状态、过程、结果和支持的管理动作 | 只调用已核对的方法；明确成功、失败和待确认 |
| 富文本渲染 | 流式 Markdown、公式、代码、表格 | 输出期间可交互；宽内容局部滚动 |

## 历史存储设计

### 列表与正文分离

历史列表只保存会话 ID、标题、工作目录、更新时间、归档状态等摘要字段。打开会话时单独读取正文，避免将所有历史图片同时传入 WebView。现有 JSON 会话继续作为正文存储，首次升级时建立必要摘要；后续保存同步更新摘要。

列表读取不能因为一份损坏记录而失败。无法读取的文件保持原样，界面列出提示。保存先写入同目录临时文件，再替换目标文件。未发生内容变化的会话不重新更新时间。

### 导入已有 Grok 会话

提供用户可见的“导入 Grok 历史”入口，使用 GROK_HOME 或默认 Grok 用户目录。读取会话元数据和 ACP 更新记录，转换为工作台的正文、计划和子任务数据。忽略未完成的末尾日志行时必须返回提示，不能伪装成完整导入。

工作台中已存在的会话 ID 保持原有标题、归档、草稿和排队数据。导入结果区分新增、已存在和无法导入。工作台内的重命名、归档不回写 CLI 文件。

### 草稿与操作顺序

未创建会话的文字和图片草稿独立保存在应用数据目录。切换会话前保存当前草稿；归档或重命名期间不能开启另一个会话操作。关闭窗口时等待已安排的保存结束。发生保存错误时给出明确提示，不能显示虚假的成功状态。

## 子任务设计

Grok 使用标准 `session/update` 发送正文和工具更新，本机测试中的子任务生命周期使用 `_x.ai/session_notification`。解析器也处理 Grok 持久化记录中的扩展更新形式。

- 主任务、已知子任务、未知会话分别路由；未知来源不会写进主对话。
- 创建、进度、完成事件按 child_session_id 合并。
- 子任务结果、工具输出和父子关系随父会话保存与导出。
- 历史恢复后，未确认仍存活的任务显示“待确认状态”。
- 手动管理动作以实际 Grok 方法和当前连接状态为准；操作进行中显示状态，错误保留在卡片内。
- 同时运行多个独立主会话、重建失效进程和跨设备同步不在本版本范围内。

## 显示与交互

长表格、公式和代码块在各自容器中滚动。公式闭合后立即渲染；未闭合片段仍可见。切换会话或筛选条件时重置组件临时状态。子任务卡片可折叠，长结果与主回答使用相同富文本组件。

## 验证与发布

1. 单元测试：摘要与正文读取、损坏文件隔离、导入幂等性、归档保留、图片草稿、子任务路由及管理请求。
2. 页面测试：打开/切换/归档/恢复、导入反馈、流式公式、代码复制、子任务按钮状态与失败提示。
3. 真实 Grok：受控子任务创建到完成；验证当前 CLI 支持的管理动作和真实事件路由。
4. 布局测试：460/640/900 内容宽度与 14/18/22 字号组合；窄窗口下输入区与工具按钮可用。
5. `npm run verify`：前端检查、测试、构建和 Rust 检查、测试全部通过。
6. 发布 Windows 安装包，更新 README、使用说明、变更记录和本页的交付状态，推送后检查 GitHub Actions 与 Release 资产。
